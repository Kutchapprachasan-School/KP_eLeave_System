# กฎการจัดทำและแก้ไขแผนงาน (Plan Versioning & Revision Protocol)

**บังคับใช้กับ:** ทุกแผนงานการพัฒนา (Implementation Plans) และเอกสารสถาปัตยกรรม (ADRs/Specs) ในโปรเจกต์นี้

---

## 📌 ข้อบังคับหลัก (Mandatory Requirements)

### 1. การกำกับ Version หรือ Revision ทุกครั้ง (Explicit Versioning)
- ทุกครั้งที่สร้างแผนงานใหม่ (`implementation_plan.md`) ให้ตั้งต้นด้วย:
  `# [ชื่อแผนงาน] (v1.0 / Rev. 0)`
- ทุกครั้งที่มีการปรับปรุง แก้ไข หรือเพิ่มเติมเงื่อนไขตามข้อเสนอแนะของผู้ใช้ ให้ขยับเลข Version / Revision ขึ้นเสมอ เช่น:
  `v1.1 (Rev. 1)`, `v1.2 (Rev. 2)`, `v2.0 (Rev. 3)`
- **ห้าม** แก้ไขแผนงานโดยไม่ระบุ Version / Revision อย่างเด็ดขาด

### 2. ตารางประวัติการแก้ไข (Revision History Table)
ทุกแผนงานต้องมีตารางสรุปประวัติการแก้ไขไว้ที่ส่วนบนสุดของเอกสาร (ใต้หัวข้อหลัก) โดยมีโครงสร้างดังนี้:

| Version / Rev | วันที่ / เวลา | การเปลี่ยนแปลงสำคัญ (Changelog) | สถานะ (Status) |
|---|---|---|---|
| `v1.0 (Rev. 0)` | YYYY-MM-DD HH:mm | แผนร่างเริ่มต้น (Initial Draft) | Superseded |
| `v1.1 (Rev. 1)` | YYYY-MM-DD HH:mm | สรุปการปรับปรุงตามข้อเสนอแนะรอบที่ 1 | Pending Approval |

### 3. การแสดงส่วนต่างของการแก้ไข (Changelog & Diff Clarity)
- ในแต่ละ Revision ต้องระบุชัดเจนว่า:
  1. สิ่งที่ **เพิ่มใหม่ (Added)**
  2. สิ่งที่ **แก้ไขหรือปรับเปลี่ยน (Changed / Refined)**
  3. สิ่งที่ **ยกเลิกหรือนำออก (Deprecated / Removed)**
- ห้ามเขียนทับข้อมูลเดิมอย่างเงียบๆ โดยไม่มีบันทึก Changelog

### 4. การอ้างอิง Version ในการสื่อสารกับผู้ใช้
- เมื่อแจ้งสรุปหรือขออนุมัติ ให้ระบุเลข Version / Revision ที่ปรับปรุงเสมอ เช่น:
  > *"ได้ปรับปรุงแผนงานเป็น **v1.1 (Rev. 1)** พร้อมบันทึกตาราง Revision History และอัปเดตลงใน Rules เรียบร้อยแล้วครับ"*
